1 信息架构分析

分析界面内容的组织方式、层级关系与导航结构。

高

1.1 右栏三级功能编号混乱，与顶栏工作流不匹配

问题描述

右侧面板从上到下依次为：② 对准 Target → ① 选择 Entry → ② 选择 Target → ③ 进针进度。而在 PuncturePointPanel 的 _init_puncture_ui 中（第 712 行），① 选择 Entry 通过 insertWidget(0, ...) 插在最前面，导致阅读时先看到 ② 再看到 ①，视觉顺序与实际流程完全颠倒。

同时顶栏 WorkflowStepper 展示的四步是：「加载 CT → 选 Entry → 连接 IMU → 对准 Target」，但右栏又包含一个独立的 ③ 路径引导面板（SimulationPanel），它与对准 Target 的功能高度重叠。

当前结构（混乱）

当前：编号顺序混乱
优化：线性编号 + 统一步骤

优化方案

  • 统一编号：右栏从上到下严格按 ① Entry+Target → ② 对准 → ③ 进针 排列，与顶栏工作流保持一致。
  • 合并 Entry 与 Target：将 Entry 和 Target 选择放在同一个 block 内，因为它们是紧密关联的穿刺计划步骤。
  • 降级 SimulationPanel：③ 路径引导面板与 ② 对准 Target 的功能高度重叠，建议将其中的「姿态锁定」功能合并到对准面板中，或作为辅助工具折叠到底部。
  • 预期效果：用户视线只需从上往下扫描一次即可了解完整流程，降低认知负荷。
中

1.2 工作模式切换位置不当，信息层级倒挂

问题描述

「穿刺训练 / 姿态观察」模式切换被放在左栏「设备 · 串口」面板内部（第 367 行 mode_combo），这是一个决定整个应用行为模式的全局配置，却被埋在设备连接的面板里。切换模式时会强制断开 IMU（第 456 行），但用户无从预知这一副作用。

此外，左栏从上到下依次是：设备 · 串口 → 影像 · DICOM → 遥测 · IMU，但实际工作流是先加载 CT 再连设备，顺序反了。

当前：模式藏在设备面板
优化：模式提至顶部 + 重排面板

优化方案

  • 将工作模式提升为顶栏一级切换：用两个并排的 pill/tab 放在 Title 下方，作为全局模式标识。
  • 重排左栏顺序：CT 导入 → 设备连接 → IMU 遥测，与实际操作流程一致。
  • 切换模式时给出非阻塞提示：用 inline toast 替代 QMessageBox，告知用户切换将断开 IMU。
  • 预期效果：用户一眼看到当前模式，减少误操作；面板顺序符合直觉，新手按从上到下点击即可完成设置。
中

1.3 对准 HUD（GuidanceArrowWidget）信息密度不足

问题描述

GuidanceArrowWidget 展示了偏差角的偏移方向 + 角度数值，但缺乏「应该往哪个方向转动探针」的直观指示。用户看到十字线上的偏移点，需要在大脑中将其映射为手部动作（例如"点在上方意味着往下转"），这在训练场景下增加了解码时间。

同时该 widget 最大只有 152×152px（第 969 行），在 1920×1080 屏幕上仅占约 8% 宽，而这是整个对准流程中最关键的实时反馈。

优化方案

  • 增大罗盘尺寸：将最大尺寸放宽到 220×220，在右栏中占据更显著的视觉权重。
  • 添加箭头动画：从偏移点画一个指向圆心的渐变箭头（"往这边转"），颜色动态映射偏差角。
  • 添加文字方向提示：在罗盘下方显示如「↑ 向上倾斜 · 向左旋转 4°」的具体操作指令。
  • 预期效果：用户无需二次解码，直接按提示方向调整探针，缩短对准时间。
低

1.4 缺少全局状态摘要面板

问题描述

顶栏 HeaderStatusPill 仅显示「IMU 已连接 · 200 Hz」或「IMU 未连接」。但训练过程中用户还需要快速了解：CT 是否已加载、Entry 和 Target 是否已选定、当前偏差角。这些关键状态分散在左侧和右侧各个面板中，没有一处汇总视图。

优化方案

  • 在顶栏添加 4 个紧凑的 status chip：[CT: ✓] [Entry: ✓] [Target: ✓] [偏差: 2.3°]
  • 每个 chip 用颜色编码状态（绿=完成，黄=进行中，灰=待定）
  • 点击 chip 可快速滚动到对应的面板区域
  • 预期效果：用户一瞥顶栏即可了解全局状态，无需滚动侧栏。

2 交互流程分析

分析操作步骤的效率、反馈及时性与流程流畅度。

严重

2.1 过多模态弹窗打断工作流

问题描述

整个流程中至少有 10 处 QMessageBox 调用（连接设备、选择 Entry、选择 Target、使用默认、校准完成、初始姿态校准、竖直标定完成、保存视角、连接观察模式、Target 重选）。这些弹窗强制用户点「确定」才能继续，严重打断操作节奏。

特别是 _on_puncture_point_selected（第 1017 行）和 _on_target_point_selected（第 928 行）在选点完成后弹出确认框，每次都在 3D 视图前面盖住——用户刚在 3D 上点完，还没看清选点位置就被弹窗遮住。

当前：弹窗打断
优化：inline toast

优化方案

  • 用顶部 toast 通知替代所有非关键弹窗：3 秒自动消失，不阻塞操作。
  • 保留弹窗仅用于关键确认：如「切换模式将断开 IMU，确定？」
  • 选点结果直接在右栏面板更新：Entry 坐标、Target 坐标、规划深度在面板内实时刷新，用户自然能看到。
  • 预期效果：操作流程顺畅无中断，3D 视图不会反复被遮挡。
高

2.2 3D 选点缺少视觉引导与模式提示

问题描述

点击「开始选择穿刺点」后，3D 视图没有任何视觉提示告知用户当前处于选点模式。鼠标悬停在模型上时指针不变化，也没有高亮效果。用户不知道是应该点击、拖拽还是旋转视角——实际上左键被 PunctureGLViewWidget.mousePressEvent 拦截用于选点（第 27 行），但这与用户"左键旋转视角"的直觉相悖。

优化方案

  • 选点模式触发时光标变为十字准星（Qt.CrossCursor）。
  • 3D 视图顶部叠加半透明条幅：「🎯 请在头部模型表面点击选择 Entry 点 | 右键取消」
  • 添加 mousemove 高亮：鼠标悬停的面片临时变色，显示点击将落在何处。
  • 右键取消选点模式，恢复到正常导航状态。
  • 预期效果：用户明确知道自己处于选点模式，减少误操作。
中

2.3 CT 加载缺少文件选择器，硬编码路径

问题描述

CTModelPanel._on_load_clicked（第 551 行）硬编码了 C:\Users\Lu\PyCharmMiscProject\needle_tracking\CT6，这意味着该应用只能由特定用户在特定目录结构下使用。如果 DICOM 数据不在该路径下，用户无法加载。

优化方案

  • 使用 QFileDialog.getExistingDirectory 让用户选择 DICOM 文件夹。
  • 在 config/ 下记录最近使用的路径，下次启动时作为默认值。
  • 预期效果：应用可在任意环境使用，无需修改代码。

3 视觉层级分析

分析颜色、字体、间距等视觉元素的优先级与对比度。

高

3.1 实时对准偏差角 — 最重要的信息被最小化显示

问题描述

对准偏差角是穿刺训练中最关键的实时反馈，但当前它被夹在 GuidanceArrowWidget 底部的一行小字中（f"{self._angle_deg:.1f}°"，Consolas 10px，第 1071-1077 行）。而 IMU 面板中的芯片欧拉角和四元数（对训练无直接帮助的原始数据）却占据了大量空间。

当前：偏差角淹没在面板中
优化：角度放大 + 方向指令

优化方案

  • 将偏差角度放大为核心视觉元素：36px+ 字号，居中对准面板顶部。
  • 添加可操作的方向指令：根据 guidance 的 x/y 分量生成自然语言提示（↑/↓/←/→ + 具体动作）。
  • 角度颜色映射增强：绿(<3°)→黄(3-6°)→橙(6-10°)→红(>10°)，整行文字底色变化。
  • 预期效果：用户一眼看清当前偏差和需要做的调整，无需在大脑中解码坐标。
中

3.2 左栏三块区域视觉权重一致，缺乏焦点引导

问题描述

左栏的三个 block（设备、影像、IMU）使用了完全相同的 PrepSection 样式（相同的标题栏、边框、间距）。在任何时刻只有一个 block 是需要用户操作的，但视觉上没有突出重点。

优化方案

  • 根据顶栏工作流状态，动态高亮当前步骤对应的 panel：标题栏变亮、添加左侧彩色竖线指示器。
  • 当前步骤的 block 默认展开，已完成步骤的 block 自动折叠。
  • 预期效果：用户视线自然被引导到下一步操作区域。
低

3.3 按钮样式语义一致性不足

问题描述

部分按钮的颜色与其含义不匹配：

按钮当前 variant问题
「重新选择穿刺点」danger红色暗示危险操作，但重选只是撤销。
「停止引导模式」danger红色暗示危险，但停止引导是正常操作。
「选择 DICOM 文件夹」primary绿色——正确（鼓励操作）。
「连接设备」primary绿色——正确。
「断开」danger红色——合理（断开确有一定风险）。

优化方案

  • danger 仅用于不可逆操作（如清理数据、删除）。
  • 「重新选择」使用 ghost 或 secondary。
  • 「停止引导」使用 secondary。
  • 预期效果：按钮颜色传达正确的操作风险语义。

4 布局与响应式分析

分析三栏布局的弹性、窗口缩放适配与侧栏可用性。

中

4.1 三栏刚性分配，侧栏不可折叠/隐藏

问题描述

QSplitter.setCollapsible(0, False) 和 setCollapsible(2, False)（第 190-191 行）禁止了左栏和右栏的折叠。在训练过程中，一旦 DICOM 加载完成且设备连接好，左栏几乎不再需要交互，但它固定占据 28% 宽度，压缩了 3D 视口的空间。同理，在对准训练时右栏的罗盘是最重要的，但当前只占 24%。

优化方案

  • 允许侧栏折叠：在 QSplitter 的 handle 上加 collapse 按钮（▶/◀ 三角形）。
  • 添加 F11 全屏 3D 模式：隐藏两侧，仅保留 3D 视图 + 浮动 HUD（罗盘叠加在 3D 角落）。
  • 1:4:1.5 的默认比例（而非 1:3:1），在对准阶段给予 3D 视图更多空间。
  • 预期效果：训练时钟爱大 3D 视图的用户可以折叠侧栏，需要设置时再展开。
低

4.2 窗口最小尺寸过大，小屏设备受限

问题描述

setMinimumSize(1024, 680)（第 375 行）意味着 1366×768 的笔记本屏幕可用空间约为 95% 宽 × 90% 高，几乎没有余地。实际上三栏布局在 900px 宽时仍然可用（如果允许左侧缩窄到 240px）。

优化方案

  • 降低最小宽度到 900px，缩小侧栏最小宽度到 240px。
  • 预期效果：1366×768 笔记本也能舒适使用。
