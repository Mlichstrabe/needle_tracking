# 双模式入口与简化界面实施规划

基线提交：`0e71e24`。设计依据：`docs/superpowers/specs/2026-09-21-mode-split-ui-workflow-design.md`。当前已完成阶段 1 的模式入口与两栏骨架、阶段 2 的固定 CT 核验、阶段 3 的协议探测骨架和阶段 4 的观察平移控制器；仍需目标硬件联调与最终 UI 收口。

## 总体数据流

```text
模式选择 → 对应两栏工作页 → 共享的 IMU / 测距采集 → 姿态、距离有效性
                                         ├→ 姿态观察平移控制器 → 3D 针体
                                         └→ 现有穿刺深度控制器 → 3D CT / 进度 / 引导
```

启动与模式生命周期由 `main.py` 和主窗口统一管理；两页复用采集、针轴计算和 3D 控件。两个模式各有自己的状态控制器，避免用穿刺状态机承担观察平移。

## 阶段 1：建立模式边界和两栏骨架

- 新增 `ui/mode_selector.py`。`main.py` 先显示小型模式选择窗口，选定模式后创建工作窗口。
- 调整 `ui/main_window.py`，模式通过构造参数传入，不再从设备连接卡片读取。布局改为左侧 3D、右侧模式工作区；观察页不创建 CT/选点流程。
- 在工作页提供「返回模式选择」。返回时按顺序停止定时器和采集、释放测距与 IMU 串口、清除零点及本次模式状态，然后销毁工作页。
- 此阶段仍允许手动连接设备，先验证切换和资源释放；暂不改变穿刺控制规则。

验收：首次启动只出现模式选择；观察页不触发 DICOM 加载；连续切换两模式 10 次，无重复窗口、悬挂线程或串口占用。

## 阶段 2：固定训练 CT 和点位

- 新增受版本控制的 `config/fixed_training_case.json`，记录该训练 CT 的非路径身份、网格变换版本、固定 Entry `[12.00, 22.84, 97.81]` mm、固定 Target `[-15.00, 25.00, 30.00]` mm 与约 73.0 mm 的预期深度。本机 DICOM 路径继续独立保存，不把绝对路径当作影像身份。
- 在 `core/dicom_loader.py` 返回并核验序列身份、切片数量及关键几何元数据；多序列、身份不符或切片异常时中止自动加载。模型生成后检查 Entry 到表面距离 ≤3 mm，规划深度与记录值相差 ≤3 mm。
- 穿刺页进入后自动加载固定 CT，成功后设置固定点和路径；失败时显示阻断原因，并仅提供重新定位同一套 CT 的入口。删除正常流程中的 Entry/Target 手动选点动作。

验收：正确 CT 自动显示固定点、路径和深度；缺失目录、错误序列、变换变化都不能进入训练就绪态。

## 阶段 3：双设备自动识别和共享采集

- 在独立后台任务中枚举串口并做限时协议探测。IMU 以有效 `0x55` 帧及校验和识别；测距以现有请求和合法响应识别。两个设备不能分配同一串口；多个匹配、无匹配、占用或超时均显示明确原因，展开人工绑定区。
- `core/device_manager.py` 现有 `connected` 只代表串口打开，自动连接不能据此判定协议成功；探测通过后才交给正式采集实例。保存人工绑定时仅保存端口提示，下次仍做协议复核。
- 将 `ui/widgets/range_depth_panel.py` 内的采集、滤波、有效性、零点逻辑抽成共享服务，原面板改为该服务的详情视图。两页使用同一套有效性信号，保留现有超时、跳变和零点清除行为。

验收：两路同为 CH340 时仍按协议正确分配；拔掉、占用、交换端口及重复进入模式均可恢复；失效信息进入工作页阻断状态。

## 阶段 4：姿态观察的锁轴平移

- 新增不依赖 Qt 的 `core/observation_translation_controller.py`，输入校准后的角速度、当前针轴、测距有效性、零点与相对距离，输出「未锁定／可移动／角度暂停／测距阻断／等待零点」及已应用位移。
- Space 和可点击按钮共用一个切换入口，只在观察页有效。进入条件为有效 IMU、测距、零点，且陀螺零偏校准已完成；校准后角速度模长暂按 ≤3°/s 连续 0.3 秒判断静止。未校准时给出原因，不把原始角速度当作已校准值。
- 进入时记录当前针轴；距离差沿锁定轴改变针尖位置。偏差 >10° 持续 0.2 秒则冻结位置，回到 ≤8° 持续 0.3 秒后补到当前有效距离；期间姿态持续更新，锁定状态保留。再次按 Space 退出。测距失效冻结位置，零点丢失则退出锁定并要求重新记录零点。
- 3D 每帧位置从控制器的已应用位移计算；右栏详情同时显示测得位移、已应用位移和轴角，便于检查冻结和补位。

验收：按 Space 前位置固定；角度暂停期间姿态变化但位置不变；恢复后补到当前值；退出后不再平移；无效读数绝不改变位置。针对进入、抖动、暂停、恢复、超时、零点丢失编写纯逻辑测试。

## 阶段 5：完成两页 UI 并清理旧流程

- 观察页右栏常显连接状态、零点按钮、平移状态和阻断原因；原始测距、测得/已应用位移、轴角、欧拉角、四元数、校准和平滑收进折叠区。
- 穿刺页右栏常显对准引导、进针深度、暂停原因和必要时的零点按钮；设备绑定、原始遥测、CT 设置、路径引导收进折叠区。移除六步条及重复状态标签。
- 保留 `core/puncture_depth_controller.py` 的 3°准入、4°暂停和三次有效样本完成判定；删除旧主窗口中已失去入口的模式切换与选点分支，并同步 README、AGENTS.md。

验收：两页均只有 3D 和右侧工作区；常用操作无需展开详情；穿刺有效性阻断及完成规则与基线一致。

## 阶段 6：验证与交付

1. 自动检查：原有穿刺测试继续通过；新增观察控制器、固定 CT 身份/几何检查和端口分配测试；执行 Python 编译检查。
2. 桌面检查：实际 OpenGL 窗口核对布局、按键焦点、CT 点位、进度和阻断文案；离屏启动只用于发现初始化错误。
3. 实机检查：在目标电脑连接 IMU 与测距模块，记录静止、转动、轴向移动、超时、拔插和模式往返日志。比较测得与已应用位移，确认暂停与补位；再验证穿刺完成。暂定 3°/s、10°、8°和持续时间可依据这批日志调整，并记录调整值。

不在本轮加入患者配准、任意 CT 的自动规划、临床入路判断或针体 STL 替换。固定 CT 原始数据不随 Git 提交；目标机器必须能访问同一序列，且须在程序中通过身份核验。
